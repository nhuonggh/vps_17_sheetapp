# SheetApp — Kế hoạch tổng hợp: Supabase → PostgreSQL VPS + Custom Google Auth + CI/CD

> File này thay thế `1.setup_sheetappai.md` và `2.conversuppbase.md` (2 file đó đã bị move ra
> ngoài repo vì chứa secret thật — SSH key, mật khẩu DB, Google client secret, mật khẩu
> registry). File này KHÔNG chứa secret thật, chỉ chứa cấu trúc/placeholder để dùng lại về sau.
> Xem thêm nguyên tắc bắt buộc ở `.specify/memory/constitution.md`.

---

## 1. Bối cảnh hiện tại (trước migrate)

- **Stack**: Next.js 16 (App Router), React 19, TypeScript, deploy hiện tại trên Vercel.
- **Auth + DB hiện tại**: Supabase (`@supabase/supabase-js`), RLS policies (`supabase_rls_policies.sql`,
  `fix_rls_public_read.sql`, `RLS_FIX_GUIDE.md`), auth sync trigger (`migrations/create_auth_sync_trigger.sql`).
- **File liên quan Supabase trong code**: `lib/supabase.ts`, `lib/supabase-server.ts`,
  `lib/auto-enrollment.ts`, các route trong `app/api/`, `app/auth/`.
- **Payment**: PayOS (`@payos/node`) — độc lập Supabase, giữ nguyên khi migrate trừ khi đụng bảng Supabase.
- **Rate limit**: Upstash Redis (`lib/ratelimit.ts`) — độc lập, giữ nguyên.

---

## 2. Đích đến (sau migrate)

- **Database**: PostgreSQL 15 chạy Docker trên VPS, container `postgres_<project>`, không còn phụ
  thuộc Supabase SDK/RLS.
- **Auth**: Google OAuth2 tự cấu hình (Google Cloud Console, tự quản Client ID/Secret) + tự phát
  hành/verify JWT (`JWT_SECRET`) — không dùng Supabase Auth.
- **Authorization**: chuyển toàn bộ RLS policy cũ thành check quyền ở application layer (API route /
  middleware), verify trên mọi request thay vì tin dữ liệu client gửi lên.
- **Hosting**: VPS tự quản (Docker + Caddy reverse proxy), không còn Vercel.
- **CI/CD**: GitHub Actions build image → push registry riêng → SSH vào VPS pull & restart container.

## 3. Hạ tầng VPS — các bước setup (mẫu, thay giá trị theo dự án)

Bảng biến số cần thay khi áp dụng cho dự án (giá trị thật lưu trong `.env` / GitHub Secrets,
KHÔNG lưu trong file này):

| Biến | Ý nghĩa |
|---|---|
| `<project_slug>` | tên slug dự án (vd: `sheetapp`) |
| `<db_password>` | mật khẩu PostgreSQL |
| `<jwt_secret>` | JWT secret |
| `<google_client_id>` / `<google_client_secret>` | Google OAuth2 credentials |
| `<domain>` | domain của dự án (vd: `sheetapp.luyenthiccxd.com`) |
| `<docker_port>` | port Docker riêng của dự án |
| `<github_repo>` | repo GitHub dự án |
| `<vps_ip>` | IP VPS |

### Bước 1 — Khởi tạo PostgreSQL

```bash
mkdir -p /opt/postgres_<project_slug>

docker run -d \
  --name postgres_<project_slug> \
  --restart always \
  -e POSTGRES_USER=<project_slug>_user \
  -e POSTGRES_PASSWORD=<db_password> \
  -e POSTGRES_DB=<project_slug>_db \
  -v /opt/postgres_<project_slug>:/var/lib/postgresql/data \
  postgres:15

docker network connect pgnet postgres_<project_slug>
```

### Bước 2 — Deploy user + SSH key

```bash
useradd -m -s /bin/bash deploy_<project_slug>
usermod -aG docker deploy_<project_slug>
su - deploy_<project_slug>
ssh-keygen -t ed25519 -C "deploy_<project_slug>@vps"   # không đặt passphrase
cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
cat ~/.ssh/id_ed25519   # copy toàn bộ → GitHub Secret VPS_SSH_KEY, KHÔNG paste vào file trong repo
exit
```

### Bước 3 — Quyền reload Caddy cho deploy user

```bash
echo "deploy_<project_slug> ALL=(ALL) NOPASSWD: /usr/bin/systemctl reload caddy" \
  >> /etc/sudoers.d/deploy_<project_slug>
```

### Bước 4 — Thư mục dự án + `.env` production

```bash
mkdir -p /home/deploy_<project_slug>/app
chown -R deploy_<project_slug>:deploy_<project_slug> /home/deploy_<project_slug>/app
nano /home/deploy_<project_slug>/app/.env
```

Nội dung `.env` (điền giá trị thật trực tiếp trên VPS, không commit):

```env
NODE_ENV=production
PORT=3000
DATABASE_URL=postgresql://<project_slug>_user:<db_password>@postgres_<project_slug>:5432/<project_slug>_db
JWT_SECRET=<jwt_secret>
GEMINI_API_KEY=<gemini_api_key>
GOOGLE_CLIENT_ID=<google_client_id>
GOOGLE_CLIENT_SECRET=<google_client_secret>
```

### Bước 5 — Caddy reverse proxy

```bash
nano /etc/caddy/conf.d/<project_slug>.caddy
```

```caddy
<domain> {
    reverse_proxy localhost:<docker_port>
}
```

```bash
systemctl reload caddy
```

### Đăng ký DB trên pgAdmin

`https://pgadmin.luyenthiccxd.com` → Servers → Register → Server:
- General → Name: `<project_slug>-db`
- Connection → Host: `postgres_<project_slug>`, Port: `5432`, Maintenance DB: `<project_slug>_db`,
  Username: `<project_slug>_user`, Password: `<db_password>`

## 4. Migrate dữ liệu Supabase → PostgreSQL VPS

### Bước 1 — Đóng hết session đang connect DB đích (nếu tái tạo)

```bash
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d postgres -c "
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE datname = '<project_slug>_db' AND pid <> pg_backend_pid();
"
```

### Bước 2-3 — Drop & tạo lại DB (nếu cần làm sạch trước import)

```bash
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d postgres -c "DROP DATABASE <project_slug>_db;"
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d postgres -c "CREATE DATABASE <project_slug>_db OWNER <project_slug>_user;"
```

### Bước 4 — Tạo extension trước khi import

```bash
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d <project_slug>_db -c 'CREATE EXTENSION IF NOT EXISTS "uuid-ossp";'
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d <project_slug>_db -c 'CREATE EXTENSION IF NOT EXISTS "pgcrypto";'
```

### Bước 5 — Dump từ Supabase + sửa extension schema

```bash
pg_dump "<supabase_connection_string>" \
  --schema=public \
  --no-owner \
  --no-privileges \
  -f ~/supabase_backup.sql

sed -i 's/extensions\.uuid_generate_v4/public.uuid_generate_v4/g' ~/supabase_backup.sql

# Verify: dòng đầu = 0, dòng sau > 0
grep -c "extensions.uuid_generate_v4" ~/supabase_backup.sql
grep -c "public.uuid_generate_v4" ~/supabase_backup.sql
```

> `<supabase_connection_string>` là connection string Postgres thật của Supabase project (chứa
> password) — chỉ gõ trực tiếp trên VPS/terminal, không paste vào file trong repo.

### Bước 6 — Import vào container

```bash
docker cp ~/supabase_backup.sql postgres_<project_slug>:/tmp/supabase_backup.sql
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d <project_slug>_db -f /tmp/supabase_backup.sql > ~/import_log.txt 2>&1
```

### Bước 7 — Verify (bắt buộc theo Constitution Principle VI)

```bash
grep -i "ERROR" ~/import_log.txt
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d <project_slug>_db -c "\dt public.*"
docker exec -i postgres_<project_slug> psql -U <project_slug>_user -d <project_slug>_db -c "
SELECT relname, n_live_tup
FROM pg_stat_user_tables
ORDER BY relname;
"
```

Migrate chỉ coi là xong khi: `import_log.txt` không có `ERROR`, danh sách bảng khớp Supabase gốc,
row count từng bảng khớp nguồn.
